# صيدليتي — تحليل المشروع (Phase 0)

آخر تحديث: 2026-10-30. الملف ده بيوصف المشروع زي ما هو فعلاً في الكود، مش زي ما المفروض يبقى.

## المشروع فين
- الكود: مستودع GitHub `bodamansour/saydaliti` (الفرع `main`). فولدر التنزيلات على جهاز صاحب الصيدلية فيه ملف باك اب المتحدة `11.gen` بس، مش الكود.
- النشر: كل push على `main` بيطبّق تحديثات قاعدة البيانات (migrations) وبعدين ينشر الـ Worker على Cloudflare، ويبني برنامج الويندوز (x64 و Win7/32-bit).

## التقنيات (Stack)
| الجزء | التقنية | الملفات |
|---|---|---|
| الواجهة (ويب + PWA) | JavaScript عادي (ES modules) من غير framework، HTML/CSS، Service Worker للشغل من غير نت | `index.html` (اللوحة)، `cashier.html`، `attendance.html`، `admin.html`، `src/*.js`، `sw.js` |
| السيرفر | Cloudflare Worker + D1 (SQLite) + R2 (ملفات الرفع الكبيرة) + Cron | `worker/src/*.js`، `worker/migrations/*.sql` |
| قاعدة البيانات | جدول واحد لكل حاجة، معرّف في `worker/src/schema.js` (الأعمدة، الصلاحيات، الروابط)، و `db.js` بيطبّق القواعد دي على كل طلب | `worker/src/schema.js`، `worker/src/db.js` |
| برنامج الكمبيوتر | Electron (33 للـ x64، و 22 لويندوز 7)، أونلاين (بيفتح الموقع) أو على الجهاز (`app://` + `src/local-db.js` على IndexedDB) | `desktop/` |
| الموبايل | Flutter WebView بيفتح نفس الموقع (Android) | `mobile/` |
| المتحدة (Genius) | قارئ ملفات الباك اب `.gen` مباشرة، ومزامنة حية للقراية من SQL Server 2000 عن طريق PowerShell | `src/genius.js`، `connector/genius/`، `desktop/genius-live.*` |
| الاختبارات | `node --test` (منطق) + Playwright (متصفح: اللوحة، النسخة اللي على الجهاز، السيرفر على Cloudflare محلياً، مزامنة المتحدة على SQL Server حقيقي في CI) | `test/`، `e2e/`، `.github/workflows/test.yml` |

## المعمارية باختصار
- **منطق مشترك واحد:** الحسابات (الرصيد بالتشغيلات، تكلفة المبيعات، الربح، المرتجعات، الطلبيات، التقارير) في ملفات pure في `src/` (`core.js`، `inventory.js`، `pos.js`، `sales-report.js`، `ordering.js` …)، وكل المنصات (ويب، ويندوز، موبايل) بتستخدم نفس الملفات. مفيش حسابات متكررة بين المنصات.
- **مصدر الرصيد:** آخر ملف اترفع من برنامج الصيدلية (أو المزامنة الحية) + اللي اتسجل في صيدليتي بعده (طلبيات، مبيعات كاشير، جرد، تحويلات) — `liveData()` في `src/inventory.js`. التشغيلات FEFO، وكل تشغيلة ليها تكلفة وسعر بيع.
- **تعدد الصيدليات (multi-tenant):** كل جدول فيه `pharmacy_id`، و`db.js` بيقصر أي قراية/كتابة على الصيدلية اللي المستخدم عضو فيها، والروابط بين الجداول بتتأكد إنها في نفس الصيدلية.
- **الصلاحيات:** 3 أدوار: `owner` (صاحب الصيدلية)، `partner` (شريك: بيشوف الأرقام بس)، `device` (جهاز الصيدلية: كاشير وحضور). كل جدول محدد مين يقرا ويضيف ويعدّل ويمسح.
- **من غير نت:** طابور عمليات على الجهاز (`src/offline.js`) بيترفع لما النت يرجع، وكل عملية ليها id ثابت فمفيش تكرار بعد إعادة الإرسال.
- **سجل التعديلات:** الجداول المهمة عليها `audit: true` فأي إضافة/تعديل/مسح بيتسجل في `audit_log`.

## ملاحظات وأخطار معروفة
1. **الأدوار محدودة:** مفيش صيدلي/محاسب/مسؤول مخزن، ومفيش صلاحيات قابلة للتعديل.
2. **بيع المنتهي والرصيد السالب:** الكاشير بيحذّر بس، مش بيمنع.
3. **مفيش استرجاع كلمة سر بالإيميل** (مفيش خدمة إيميل متوصلة)؛ تغيير كلمة السر موجود.
4. **Cloudflare الخطة المجانية** — لازم الخطة المدفوعة قبل صيدليات تانية (حدود الطلبات والـ CPU).
5. **الكتابة في المتحدة (جرد):** مش هتتعمل دلوقتي، بقرار صاحب المشروع. «ملف تصحيح للمتحدة» موجود، بس محتاج يتنزّل في المتحدة بإيدك.
6. **الموبايل WebView** — مفيش إشعارات push native لسه.
7. **الذكاء الاصطناعي:** مفيش أي جزء AI لسه؛ التحليلات الموجودة حسابات ثابتة (deterministic).
