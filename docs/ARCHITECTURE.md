# صيدليتي — بنية النظام

آخر مراجعة: 2026-10-30. المرجع التنفيذي هو الكود؛ هذا الملف يشرح الحدود ومسارات البيانات الحالية.

## المكونات

- **واجهة مشتركة:** صفحات HTML وملفات JavaScript عادية تحت الجذر و`src/`. نفس قواعد البيع والمخزون والتقارير تُستخدم على الويب وElectron وAndroid WebView.
- **Worker:** `worker/src/index.js` يخدم الأصول الثابتة وواجهات الدخول والبيانات وRPC ورفع الملفات، ويستدعي وظائف التقارير المجدولة.
- **D1:** مصدر البيانات السحابي. `worker/src/schema.js` يجمع تعريف الجداول والحقول والصلاحيات، و`worker/src/db.js` يتحقق من الدور والصيدلية والقيم وروابط السجلات.
- **R2:** يخزن لقطات البيانات الكبيرة وصور الأصناف. يحتفظ D1 ببيانات وصفية ومراجع، لا بمحتوى اللقطة الكبير.
- **تخزين محلي:** وضع Windows المحلي يستخدم IndexedDB عبر `src/local-db.js`. وضع الويب غير المتصل يخزن طابور العمليات والنسخة اللازمة للعمل مؤقتًا على الجهاز.
- **التكامل مع United:** استيراد ملف `.Gen` على الجهاز أو تشغيل وصلة قراءة PowerShell؛ لا يكتب التطبيق إلى قاعدة United مباشرة.

## تدفقات أساسية

### البيع والمخزون

1. الواجهة تقرأ البيانات الحالية واللقطة التي وصلت من United أو الوصلة.
2. `src/inventory.js` يركّب المخزون مع المشتريات والمبيعات والتعديلات اللاحقة ويحسب التشغيلات وFEFO.
3. الكاشير يسجل الفاتورة كسجل `pos_sales` واحد يتضمن السطور والإجماليات وطريقة الدفع، ويحفظ الطابور محليًا عند انقطاع الإنترنت.
4. عند الاتصال، تُعاد العمليات ذات المعرّفات الثابتة إلى Worker لتقليل التكرار. التحقق من الأدوار والروابط يتم على السيرفر.

### المستخدم والصيدلية

- التسجيل ينشئ حسابًا، ثم تنشأ العضوية والصيدلية والفرع الرئيسي عبر RPC.
- الجلسة السحابية تحمل رمزًا عشوائيًا؛ قاعدة البيانات تحفظ تجزئة الرمز فقط. صلاحيتها 60 يومًا.
- جميع الجداول الحساسة تمر بقواعد `TABLES` في `schema.js`. الاستعلامات والعمليات تُقيد بعضوية الصيدلية، وتُراجع روابط الفرع والعميل والموظف.
- الأدوار الحالية ثابتة: `owner`, `partner`, `device`, `pharmacist`, `accountant`, `stock`. لا توجد صلاحيات قابلة للتخصيص أو نطاق عضوية حسب الفرع.

### المهام المجدولة

- تقرير الصباح: الساعة 06:00 UTC حسب `worker/wrangler.toml`.
- تذكيرات المرضى: عند الدقيقة 15 من كل ساعة.
- Miniflare المحلي لا ينفذ Cron تلقائيًا؛ يجب اختبارها بأداة Cron المحلية أو في بيئة Cloudflare منفصلة.

### المرتجعات

- يتحقق Worker من الإيصال والكمية قبل الحفظ، ثم يحفظ مرتجع `pos_sales` باستعلام SQL مشروط داخل دفعة D1 الذرية. يعيد الاستعلام التحقق من المتبقي وقت الإدخال، فيُرفض الطلب الثاني إذا سبق طلب متزامن واستهلك الكمية. لا يحتاج ذلك إلى ترحيل للمخطط.

## النشر

- `.github/workflows/cloudflare.yml` يطبق ترحيلات D1 البعيدة ثم ينشر Worker عند الدفع إلى `main` إذا كانت أسرار GitHub موجودة.
- `.github/workflows/desktop.yml` يبني مثبت Windows 64-bit ونسخة Electron 22 للأجهزة القديمة.
- `.github/workflows/android.yml` ينشئ مشروع Flutter ويصدر APK.
- اختبارات الحسابات والواجهة والسيرفر في `.github/workflows/test.yml`.

## قيود وقرارات مفتوحة

- البيانات التشغيلية السحابية مركزها D1؛ لذلك يلزم اختبار الاستعادة وخطة نسخ احتياطي قبل توسيع الاستخدام التجاري.
- ربط المستخدم بفرع يحتاج قرارًا قبل تعديل المخطط: جدول ارتباط متعدد الفروع أو إعداد عضوية محدود، مع ترحيل واختبارات عزل.
- أُضيف اختبار API يثبت رفض أحد مرتجعين متزامنين؛ نتيجة الاختبار بعد التغيير ما زالت تنتظر CI لأن إعداد D1 المحلي فشل في Wrangler.
- تفاصيل نشر الإنتاج ومفاتيحه في [`DEPLOYMENT_GUIDE.md`](DEPLOYMENT_GUIDE.md)، وتعريف الجداول في [`DATABASE_SCHEMA.md`](DATABASE_SCHEMA.md).
